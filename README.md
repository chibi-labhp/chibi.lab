# chibi lab. 公式サイト

> **⚠ 現在は検証中のため、検索エンジンにインデックスされないよう設定しています**
> （`robots.txt` で全ページのクロールを禁止し、`index.html` / `admin.html` に
> `<meta name="robots" content="noindex, nofollow">` を追加済み）。
> 本公開する際は、以下を実施してください。
> 1. `robots.txt` の `Disallow: /` を削除する（またはファイル自体を削除）
> 2. `index.html` の `<meta name="robots" ...>` 行を削除する
>    （`admin.html` の方はそのまま `noindex` を残すことを推奨します。
>    管理ページが検索結果に出る必要はないためです）

東京理科大学 サイエンスコミュニケーションサークル chibi lab. の公式サイトです。
2024年ごろまでFC2ホームページ（chibilab.web.fc2.com）で運用していたサイトを、
GitHub Pagesに移行したものです。

## ファイル構成

```
index.html   … トップページの骨格（HTMLは基本これ以上いじらない）
style.css    … 見た目（色・フォント・レイアウト）はすべてここに集約
script.js    … サイトの文言・お知らせ・イベント情報・ギャラリー写真は
                ここのSITE/TOPICS/EVENTS/GALLERYを書き換えるだけでOK
admin.html   … 非エンジニアでもブラウザだけでscript.jsを編集・公開できる管理ページ
admin.js     … admin.htmlの動作本体（見た目と処理を分けてあるだけで、常に
                admin.htmlとセットで使う）
images/      … ギャラリー写真置き場
images/brand/… ロゴ・マスコット「ラボくま君」の画像（差し替え不要。ヘッダー・
                トップページ・お問い合わせ欄で使用）
.nojekyll    … GitHub PagesでJekyll変換を無効にするための空ファイル（削除しないこと）
```

**見た目を変えたいときは `style.css`、内容（イベント・写真）を更新したいときは
`script.js` を触ればOKです。`index.html` を編集する必要は基本ありません。**

## 後任向け：日常の更新手順

### 方法A：admin.html を使う（おすすめ・コード不要）

1. `admin.html` をブラウザで開く（公開後は `https://<ユーザー名>.github.io/<リポジトリ名>/admin.html`）
2. 「STEP 1」でリポジトリ名（`chibi-labhp/chibi.lab`）と
   GitHubのアクセストークンを入力し「読み込む」を押す
   - トークンの作り方は下の「GitHubトークンの発行方法」を参照
3. 表示されたフォームで内容を編集する
   - **STEP 2 サイト全体の文言**：ヒーローのキャッチコピー、ABOUT本文、
     お問い合わせ文言・メールアドレス・フォームURL、SNSリンクなど
   - **STEP 3 ページの並び順**：ABOUT・お知らせ・イベント情報・ギャラリー・
     STEP7で作った追加セクション（複数作った場合は1つ1つ）の表示順を、
     ドラッグで自由に入れ替えられる（ナビゲーションや見出しの番号も自動で
     合わせて更新される）。追加セクションをABOUTより上に持ってくるなど、
     固定のブロックと自由に混ぜて並べられる。各固定ブロックの「非表示にする」
     を押すと、そのブロックごとサイトから消せる（中身は消えず、下に出る
     「＋ ○○を表示する」ボタンでいつでも元に戻せる）。追加セクションの行には
     「削除」ボタンがあり、STEP7まで移動しなくてもここから直接削除できる
   - **STEP 4 お知らせ**：新しいお知らせを「＋ お知らせを追加」で好きなだけ追加
     できる（日付・タイトル・本文＋画像は任意。画像を付けると「TOPICS」に写真
     付きで表示される）
   - **STEP 5 イベント情報**：日時・場所・タイトル・説明文（「活動記録」に表示）
   - **STEP 6 ギャラリー**：写真キャプション・画像ファイル名
   - **STEP 7 新しいセクション**：「＋ セクションを追加」でABOUTやEVENTSと
     同じような独立したセクションを自由に作れる（工作紹介・リンク集・クイズなど）。
     ナビゲーションにも自動で表示される。セクションの中には「＋ 項目を追加」で
     カード（タイトル・説明・画像・リンクはいずれも任意）を好きなだけ並べられる。
     サイト上でどこに表示するか（一番上に持ってくる、GALLERYの後ろにする等）は
     STEP3で調整する
   - ギャラリー写真・お知らせ・セクション項目の画像は、各画像欄の
     **「画像を選ぶ」ボタン**からパソコン・スマホ内の写真を直接選ぶだけで
     アップロードでき、ファイル名が自動で入力される（GitHub側で事前に
     `images/` フォルダへアップロードしておく必要はない）。すでにファイル名が
     分かっている場合は、これまで通り直接入力欄に書いてもよい
   - 画像欄の下には小さくサムネイルが表示され、ファイル名の入力ミスにその場で
     気づける（画像が見つからない場合は何も表示されない）
   - カードの入力欄・ボタン以外なら**どこを掴んでもドラッグ**でき、お知らせ・
     イベント・写真・セクション・セクション内の項目の並び順を自由に入れ替え
     られる（スマホ・タブレットのタッチ操作にも対応）。並び替わる瞬間は
     スッと動くアニメーションが付くので、どこに移動したか分かりやすい
4. 操作を間違えたら **「↶ 元に戻す」**で1つ前の状態に戻せる（何度でも押せる）。
   すべての変更をやめて最初からやり直したいときは **「読み込み時点に復元」**を押す
   （GitHubから読み込んだ直後の状態に一括で戻る）
5. 保存する前に **「プレビュー」ボタン**を押すと、今の編集内容が実際のサイトの
   見た目でその場に表示される（まだGitHubには保存されていないので、何度でも
   確認・やり直しができる）
6. 問題なければ「保存してサイトに反映」を押すと、GitHub上の `script.js` が
   自動で書き換わり、1〜2分後に公開サイトに反映される（保存が終わると
   「公開サイトを見る」リンクが出るので、そのまま仕上がりを確認できる）。
   `Cmd/Ctrl + S` キーでも同じ操作ができる

### 誤操作・閉じ忘れ対策

- 保存していない変更があるまま**タブを閉じよう（別のページに移動しよう）とすると
  確認メッセージが出る**ので、うっかり閉じてしまう事故を防げる
- 編集中の内容は数秒おきに自動でブラウザに保存されている。**保存し忘れたまま
  タブを閉じてしまっても**、次に同じリポジトリを「読み込む」と「復元しますか？」
  と聞かれるので、続きから再開できる（GitHubのトークンなど認証情報は保存されない）
- 一度リポジトリ名を入力して読み込むと、次回からは**リポジトリ名が自動で入力**
  される（トークンは安全のため毎回入力が必要）

> `admin.html` は誰でも開けるページです。トークンはこのページ内（ブラウザ）に
> 保存されるだけで外部には送信されませんが、**パスワードのように扱い、他人と
> 共有しないでください。** 心配な場合は使い終わったらブラウザのタブを閉じれば
> 情報は残りません。

### 方法B：script.js を直接編集する（コードが読める場合）

1. GitHub上で `script.js` を開き、鉛筆マーク（Edit）をクリック
2. 冒頭の `SITE`（サイト文言）・`TOPICS`（お知らせ）・`EVENTS`（イベント情報）・
   `GALLERY`（ギャラリー写真）・`SECTIONS`（追加セクション）の中身だけを書き換える。
   `TOPICS` と `EVENTS` の新しい項目は配列の先頭に追加する
3. ページ下部の「Commit changes」で保存すると、1〜2分でサイトに反映される

**`SITE` / `TOPICS` / `EVENTS` / `GALLERY` / `SECTIONS` 以外の部分
（`renderSite()` より下）は触らないでください。** 表示の仕組みが壊れます。

`SECTIONS` を直接編集する場合、各セクションには一意な `id`（英数字とハイフンのみ、
ページ内リンク・ナビゲーションのアンカーに使われます）を自分で指定してください。
admin.html経由で追加した場合は、ナビゲーション表示名から自動で作られます。

## GitHubトークンの発行方法（admin.html用）

1. GitHubにログインし、右上のアイコン → **Settings**
2. 左メニュー一番下の **Developer settings**
3. **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
4. 設定項目：
   - **Repository access**: 「Only select repositories」を選び、このサイトの
     リポジトリだけにチェック（他のリポジトリに影響しないようにするため）
   - **Permissions** → **Repository permissions** → **Contents** を
     「Read and write」に変更
   - 有効期限（Expiration）は90日など短めに設定し、切れたら作り直すのが安全
5. **Generate token** を押すと `ghp_...` から始まるトークンが表示されるので、
   その場でコピーして `admin.html` に貼り付ける（**この画面を閉じると二度と
   表示されないので注意**）

## GitHub Pagesでの公開設定

1. このフォルダの中身をGitHubリポジトリ（`chibi-labhp/chibi.lab`）にpushする
2. リポジトリの **Settings → Pages** を開く
3. **Source** を「Deploy from a branch」、**Branch** を `main` / `/(root)` に設定
4. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される
5. `admin.html` もそのまま同じ場所に置いておけば
   `https://<ユーザー名>.github.io/<リポジトリ名>/admin.html` からアクセスできる

`.nojekyll` ファイルは、GitHub Pagesの標準ビルド処理（Jekyll）を無効にして
そのまま静的ファイルとして公開するためのものです。中身は空でよいので、
削除しないでください。

## FC2版サイトから引き継いだもの・引き継がなかったもの

旧サイト（`chibilab-50/` フォルダ）を確認した結果です。

- **「FC2掲示板」は旧サイト内に見つかりませんでした。** 使われていなかったと
  思われます。
- **問い合わせ機能はすでにGoogleフォーム＋Gmailに移行済みでした。** 新サイトの
  CONTACTセクションでも、旧サイトで実際に使われていたGoogleフォームのURLと
  問い合わせ用メールアドレス（`chibi.lab.chibi@gmail.com`）をそのまま引き継いで
  います。実験教室等の依頼はメール、取材等の軽いお問い合わせはフォーム、という
  旧サイトの使い分けもそのまま維持しています。
- **FC2アクセスカウンター（訪問者数表示）は引き継いでいません。** GitHub Pages
  では動作しない機能のため、代替が必要であれば以下のような無料サービスの利用を
  検討してください（本サイトには未導入）。
  - [GoatCounter](https://www.goatcounter.com/) … 軽量・プライバシー配慮型の
    無料アクセス解析。`<script>` タグ1行を `index.html` に追加するだけで導入可能
  - Google Search Console … 検索経由の流入や掲載順位を無料で確認できる
    （アクセスカウンター表示ではなく解析ツールですが、実用上はこちらの方が有用）

## ギャラリー写真について

旧サイトの2014〜2016年の活動報告から、代表的な写真18枚を厳選して
`images/` に移行しています（ファイル名は検索エンジンにも分かりやすいよう
`chibilab-（イベント種別）-（年月）.jpg` の形式にリネーム済み）。
2014年より前・2017年以降の写真を追加したい場合は、`images/` に画像を追加し、
`script.js` の `GALLERY` 配列に1行追加してください（同じ書式を真似ればOKです）。
